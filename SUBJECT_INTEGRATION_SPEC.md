# SUBJECT_INTEGRATION_SPEC — как подключить предмет

Практический шаблон подключения предмета к платформе EGE CORE.
Механизм уже работает (предмет — сущность первого класса, данные изолированы
по строкам `subject`); этот документ говорит, **какие реальные данные нужно
передать**, чтобы предмет запустился полностью. Никакого фейкового контента:
пустой предмет существует (`status: "empty"`, заглушка «Материалы пока готовятся»),
полный — только на реальных данных.

Связанный код: `SUBJECTS` в `server/server.py` (~строка 98), `install_catalog()`,
`_build_catalog_payload()`, `ensure_subject_schema()`, `js/data.js` (DataAPI),
`js/state.js` (прогноз/XP/онбординг), `js/app.js` (маршруты, `EMPTY_SUBJECT_ROUTES`,
онбординг `STEPS()`).

---

## 1. Что такое «предмет» в архитектуре

Предмет = **одна запись в `SUBJECTS`** + контент в каталоге с привязкой к нему.
Никаких `if basic_math` по коду: все системы читают конфиг предмета
(`subjects_payload()`, `catalog.subject`, `catalog.forecast`), а не хардкод.

```python
SUBJECTS = {
    "profile_math": {
        "id": "profile_math",
        "title": "Профильная математика",
        "short": "Профиль",
        "status": "ready",          # ready | empty
        "forecast": {
            "weights": {...},       # skill_id -> первичные баллы
            "total": 32,            # сумма весов
            "scale": [...],         # первичные -> тестовые (длина total+1)
        },
    },
    "basic_math": {
        "id": "basic_math",
        "title": "Базовая математика",
        "short": "База",
        "status": "empty",          # контента нет — только заглушка
        "forecast": None,           # появится вместе с весами шкалы
    },
}
```

- `status: "ready"` — полный цикл: каталог, диагностика, прогноз.
- `status: "empty"` — предмет существует, онбординг ведёт коротким путём
  (предмет → имя, без уровня/цели/диагностики), все контентные маршруты
  (`EMPTY_SUBJECT_ROUTES` в `js/app.js`: path, skill, training, session,
  practice, boss, daily, review, lesson, errors, trials, stats) показывают
  заглушку «Материалы пока готовятся», `forecast()` возвращает
  `{empty: true}`, `nextStepCandidates()` — `[]`.
- Новый предмет (русский, общество, …) = новая запись + контент ниже.
  Порядок в `SUBJECTS` = порядок показа в онбординге и селекте.

Данные пользователя изолированы: **все 19 пользовательских таблиц несут
колонку `subject`**, чтение/запись/derive — строго `WHERE user_id AND subject`.
`user_subjects` хранит пер-предметный профиль (`onboarded, self_level, goal_id`);
`users.current_subject` — текущий предмет (переживает перезагрузку);
`account_id` стабилен при смене предмета, меняется только по «Сбросить прогресс».
Две страницы данных: возврат к предмету восстанавливает всё как было.

## 2. Обязательное для любого предмета (минимум для `status: "ready"`)

| # | Сущность | Где лежит | Минимум |
|---|----------|-----------|---------|
| 1 | Запись предмета | `SUBJECTS` в `server.py` | `id, title, short, status, forecast` |
| 2 | Разделы (части) | `categories` каталога → таблица `topics` | ≥1 (например `part1`) |
| 3 | Темы/навыки | `skills` каталога → таблица `skills` | ≥1, у каждой `id, name, cat, order, ege` |
| 4 | Задания | `tasks` каталога → таблица `tasks` | ≥1 с полными полями (§3) |
| 5 | Миссия | `missions` (по одной на навык — конвенция профиля) | `id, skill, title, desc, tasks[], xp, diff` |
| 6 | Ежедневная подборка | `app_config: daily[:subject]` | `{skill, target, xp, title}` |
| 7 | Цели по баллам | `app_config: goals[:subject]` | `[{id, label, desc}]`, ≥1 |
| 8 | Диагностика онбординга | `app_config: diagnosticTasks[:subject]` | массив id заданий (может быть `[]` только у `empty`) |
| 9 | Прогноз | `SUBJECTS[id].forecast` | `weights` на **все** skills, `total` = сумма, `scale` длиной `total+1` |

Без п. 9 предмет технически откроется, но `forecast()`/`forecastTopGains()`
вернут `empty` (как у базы сейчас). Без п. 8 онбординг готового предмета
упадёт на пустой диагностике — для `ready` нужен ≥1 диагностический id.

Необязательное (есть дефолты): `lessons` (без них тема считается на 100% из
практики, см. §5), `bosses` (испытания скрываются, если не на что сослаться),
`achievements` (глобальные, общие на все предметы), `visualAssets/visualAudit`.

## 3. Поля сущностей (обязательные помечены ★)

### 3.1 Тема (skill)

```json
{ "id": "n01_planimetry", "name": "№1 — Планиметрия", "cat": "part1", "order": 0, "ege": "№1" }
```

Все поля ★. `id` — глобально уникален (он же FK в заданиях/уроках/миссиях).
`cat` — id раздела, `order` — порядок на «Пути», `ege` — подпись номера.
Установка: `install_catalog()` пишет `skills` с `subject=<предмет>`; чужие
предметы их не видят (`WHERE subject=?` в `_build_catalog_payload`).

### 3.2 Задание (task) — 21 поле

```
★ id, skill, sub, num, diff, text, answer, hint, hints[3], solution,
★ type, valueType, points, example, source, sourceId, status
  note?, visual? | mathVisual?, selfCheck? (для extended)
```

Разбор по конвенции профиля (`server/catalog.json`, 49 заданий):

- `id` ★ — уникален (`n01_p1`: номер + порядковый). Ссылки: `missions[].tasks`,
  `diagnosticTasks`, `INDEPENDENT_TASK.taskId` в уроках, история попыток.
- `skill` ★ — id темы. FK: чужой skill в снапшот не пишется и XP не даёт
  (`write_state`/`derive_stats` фильтруют по предмету навыка).
- `sub` ★ — подтема строкой («Описанный четырёхугольник, периметр»).
  Группировка ошибок и подписи в UI.
- `num` ★ — номер в экзамене («№1»). Отображается чипом в карточках.
- `diff` ★ — сложность 1–5. Входит в формулу XP
  (`attempt = 6 + diff·2`, `bonus = 10 + diff·5`) и в подбор daily.
- `text` ★ — условие. Проходит через `mathText()` (KaTeX): латиница/символы
  `%`, дроби, `log`, тригонометрия — по правилам из навыка (аудит
  `scripts/katex_audit.js`, 0 толерантности к красным формулам).
- `answer` ★ — **единственное простое значение**: целое, десятичная дробь,
  бес пробельное выражение (`6x-2`), дробь (`3/4`). Проверка — `checkAnswer()`
  в `js/state.js`: strip spaces, lowercase, запятая→точка, толерантность 1e-6,
  дроби через `n/d`, множественные корни — полным набором через запятую.
  Никогда не класть сюда доказательство/прозаичный ответ — такое задание
  обязано быть `extended_answer` + `selfCheck: true` (самопроверка, не автопроверка).
- `hint` ★ (краткая) + `hints[3]` ★ (лестница H1→H3). Правила: H1 — направление
  без чисел решения; H2 — конкретный следующий шаг с числами условия, без
  финального вычисления; H3 — останавливается на предпоследнем шаге,
  **ответа нет ни в каком виде** (десятичном, дробном, словами «получится 10»).
  Запрещены диктовки («Запиши как pi/2», «2·4 = 8»). Механическая проверка —
  `scripts/check_hints.py`, требуется 0 ошибок.
- `solution` ★ — шаблон: `Дано: …` → `План: …` → нумерованные шаги с
  вычислениями → `Ответ: …` (совпадает с `answer` дословно).
- `type` ★ — `short_answer` (35 в профиле) | `extended_answer` (14).
  Развёрнутые: только самопроверка (`selfCheck: true` обязательно),
  через `checkAnswer` в интерфейсе не проверяются.
- `valueType` ★ — подпись формата ответа у поля ввода (12 значений в профиле:
  «целое число» ×27, «конечная десятичная дробь» ×8, …). Новому предмету —
  свой словарь; поле рендерится через `answerFormatCaption()` — без call-site
  в UI останется невидимым.
- `points` ★ — первичные баллы задания (профиль: ч.1 — по 1, ч.2 — 2–4).
- `example`, `source`, `sourceId`, `status` ★ — происхождение.
  В профиле все 49: `sourceId` вида `2027-14-01`, `status: "official-demo-2027"`,
  `source` — «Демоверсия ЕГЭ-2027 проф., задание …». Smoke-тест требует эти
  инварианты — для нового предмета задать свою шкалу статусов, но поля держать.
- `note` — свободная пометка (не рендерится ученику).
- `visual` **или** `mathVisual` (взаимоисключительно):
  - `visual: {required: true, assetId: null, note}` — официальный рисунок
    существует, но в сборке его нет → задание **заблокировано** (§8).
    Разблокировка = положить файл в `assets/tasks/<num>/` + запись
    в `visualAssets` + `assetId` + статус в `visualAudit.taskStatuses`.
  - `visual: {required: false/нет}` / отсутствует — текстовая задача.
  - `mathVisual: {type, objects|nodes|…}` — декларативная схема движка
    `js/mathvisual.js` (типы: `coordinate_geometry, vector_diagram,
    function_graph, derivative_graph, triangle, quadrilateral, polygon,
    circle_geometry, 3d_solid, probability_diagram, probability_tree`).
    Новый тип фигуры = расширение движка, а не разовый asset.

### 3.3 Урок (lesson)

```json
{ "id": "lesson_n01_opisannye", "skill": "n01_planimetry",
  "title": "Описанные четырёхугольники", "xp": 150, "steps": [...] }
```

- `xp` ★ = `60 + 10·steps` (у всех 20 уроков профиля; иначе недоплата/переплата
  завершения — анти-фарм считает по `completedLessons` PK).
- Шаги, типы: `EXPLANATION` (теория: `title?, text`), `FOCUS` (доска:
  `text, board[{t, id?}], highlight[id]`), `ACTION` (проверяемый вопрос:
  `title?, text, answer, hints[3], solution, errorType, xp 10–15`),
  `FEEDBACK` (`tone, text`), `INDEPENDENT_TASK` (`taskId` из банка + `text,
  hints[3], solution` — `taskId` обязан существовать и не быть blocked,
  иначе финальный шаг рендерится пустым).
- Правила ACTION те же, что у заданий: атомарный ответ, 3 хинта без диктовки,
  решение по шаблону, `errorType` на русском. `lesson.xp` и сумма `step.xp`
  (потолок `_lesson_steps_caps`) — раздельные награды завершения и шагов.

### 3.4 Миссия / Босс / Достижение / Daily / Цели / Диагностика

- **Миссия**: `{id, skill, title, desc, tasks[id…], xp, diff}`. Конвенция профиля:
  одна миссия на навык (`m-n01_planimetry`, xp 50). Пустая `tasks: []`
  (все задачи заблокированы) — валидна: UI показывает «нет задач», а не ошибку.
- **Босс**: `{id, cat, title, desc, size, xp, unlockAt}`. `cat` — раздел
  **своего** предмета (чужие отфильтровываются); `unlockAt` — порог среднего
  прогресса для разблокировки. Профиль: `boss-part1` (size 10, xp 120,
  unlockAt 40), `boss-part2` (size 6, xp 160, unlockAt 20).
- **Достижения**: глобальные (8 в профиле: first-solve, hundred, series20,
  nohints, comeback, …), триггеры в `checkAchievements()` предметно-независимы.
  Новому предмету свои не нужны, если механики те же.
- **Daily**: `{skill, target, xp, title}` (профиль: target 6, xp 60).
  Ключ `daily:<subject>`; legacy `daily` — фолбэк. Пустому предмету пишется
  честное пусто `{skill:"", target:0, xp:0, title:""}` — подборка из нуля
  задач не стартует, `Session.start` с пустым списком показывает тост.
- **Цели**: `[{id, label, desc}]` (профиль: g60/g80/g95). Ключ `goals:<subject>`;
  **без legacy-фолбэка для не-профиля** — чужая шкала баллов не подсовывается.
- **Диагностика**: `[taskId…]` (профиль: 5 штук). Ключ `diagnosticTasks:<subject>`.
  Задания обязаны существовать и быть решаемыми (не blocked) — иначе онбординг
  готового предмета нечем проходить.

## 4. Файлы, таблицы, ключи (куда класть)

| Слой | Что заполнить |
|------|---------------|
| Контент | `server/catalog.json`: `categories, skills, tasks, lessons, missions, bosses, achievements?, daily, goals, diagnosticTasks, visualAssets?, visualAudit?` |
| Конфиг предмета | `SUBJECTS` в `server/server.py` (+ веса/шкала прогноза) |
| Ассеты | `assets/tasks/<номер>/…` (svg/png/jpg) + записи `visualAssets` (`{id, src, type, alt, width?, ratio?, source, sourceId, taskId?, description}`) |
| БД (каталог) | `topics, skills(+subject), tasks, lessons, missions, mission_tasks, bosses, achievements, app_config` — всё пишет `install_catalog()` (UPSERT; **не удаляет** stale-строки — удалённые из json чистить вручную + рестарт) |
| БД (пользователь) | создаётся миграцией `ensure_subject_schema()` автоматически: `subject` во всех 19 таблицах, `user_subjects`, `users.current_subject`. Руками ничего не делать |
| Frontend | ничего править не нужно: каталог приезжает через bootstrap с `subjects/subject/forecast`; веса — из `catalog.forecast`, фолбэк — константы профиля в `js/state.js` |

Предметные ключи `app_config`: `daily:<subject>`, `goals:<subject>`,
`diagnosticTasks:<subject>` (профилю дублируются при установке; базе —
честное пусто). Общие на всех: `visualAssets`, `visualAudit`.

## 5. Алгоритмы и их предметные параметры

Всё ниже — **общее, работает из коробки**; предметным является только конфиг.

- **Прогноз** (`forecast()`, `forecastSkillMastery()`, `forecastTopGains()`):
  веса навыков → взвешенное среднее → `primary = mastery/100·total` →
  `scale[round(primary)]`, вилка `±(12…3)` по покрытию. Параметры предмета:
  `weights` (на **все** skills; новый skill без веса — эвристика 2/1, так не
  оставлять), `total`, `scale`. Тюнинг затухания (`FORECAST_DECAY_DAYS=45`,
  `FORECAST_FULL_VOLUME=12`) — глобальный, менять только с прогоном
  `test/forecast.js` + перекалибровкой порогов `nextStepCandidates()`.
- **Прогресс навыка** (`skillProgress()`, 40 теория + 60 практика):
  теория = доля завершённых уроков навыка; практика = `min(1, solved/10) ·
  accuracy`. Без уроков тема считается на 100% из практики. Веса 40/60 —
  глобальные (смена сдвигает все абсолютные значения → прогон
  `test/recommender.js`).
- **Рекомендации** (`nextStepCandidates()`): доучить открытый урок 92 >
  урок слабой теории 68–82 > разбор ошибок ~52+ > миссия/босс/daily.
  Пустому предмету возвращает `[]` (экран — заглушка).
- **XP** (единый калькулятор `derive_stats()`, зеркало `attemptXp()` в js):
  попытка `6 + diff·2` всегда; верный `+10 + diff·5` (×0.6 хинт1, ×0.3 хинт2,
  0 при повторе/показе ответа); закрытая ошибка +15 (раз на задание, только
  если есть верная попытка); урок `60 + 10·steps` + шаги (потолок
  `_lesson_steps_caps`); миссии/боссы/daily по каталогу; milestone +50/уровень
  (fixed-point). **Всё фильтруется по предмету снапшота** — чужие id дают 0.
  Новое XP-источник: награда в js через `addXp` + зеркало в `derive_stats` +
  идемпотентность по durable-факту; клиентские числа не доверяются.
- **Уровни**: `xpForLevel(n) = 400 + 120·(n−1)` — глобально.
- **Серии/дни** (`touchStreak()`, `todayActivity()`): московская дата
  (`Europe/Moscow`), streak — consecutive days. Глобальная механика,
  счётчики — пер-предметные (`user_stats`, `activity_history`).
- **Ошибки**: открытые (`user_errors` + `lesson_step_errors`) → разбор →
  `resolved` + бонус. Всё в разрезе предмета.
- **Сложность/уровень знаний**: `selfLevel` (zero/base/confident) — настройка
  **внутри** предмета (`user_subjects`), на контент не влияет, прогресса
  не создаёт. Отдельной «настройки сложности» предмета нет — сложность живёт
  в `diff` заданий и подборе daily/миссий.

## 6. Маршруты, страницы, пустые состояния

Маршруты (`js/app.js`): `#/dashboard, path, skill/<id>, training,
practice/<mission>, boss/<id>, daily, review, session, lesson/<id>, errors,
trials, stats, profile`. Все читают **текущий** каталог/стейт — развести
предметы негде по построению. В пустом предмете контентные маршруты
(`EMPTY_SUBJECT_ROUTES`) → `screenEmptySubject` («Материалы пока готовятся»),
dashboard показывает hero + заглушку вместо прогноза/шага/навыков,
topbar/sidebar — «скоро» вместо чисел. Переключатель — селект в профиле
(карточка «Данные», над «Сбросить прогресс») + дубли на заглушках; шапка
предмета не содержит. Онбординг: `stepSubject` первый после приветствия;
пустой предмет — короткий путь (предмет → имя), готовый — полный
(уровень → цель → диагностика(5) → итог → имя).

## 7. Ограничения и флаги доступности

- `visual.required && !visual.assetId` — канонический предикат блокировки
  (зеркала `task_has_missing_visual` / `DataAPI.taskHasMissingVisual`):
  задача остаётся в БД для аудита, из `catalog_payload` (задачи + списки
  миссий) исключается, видна только в `/api/admin/blocked-tasks`.
  Клиентские выборки (`practiceTasks()`, миссии) фильтруют вторым слоем.
- `INDEPENDENT_TASK` на blocked-задачу = пустой финальный шаг без ошибки —
  проверять при сборке уроков.
- `validate_state`/`write_state`/`derive_stats`: мусор скипается позаписно,
  весь PUT не отклоняется; коллекции капнуты (`MAX_*`); `subject` обязан быть
  известным, иначе 400.
- `install_catalog()` — только UPSERT: удалённое из json лежит в SQLite,
  пока не удалить вручную (`tasks` + `mission_tasks`, `task_attempts`,
  `user_errors`, `diagnostics`) + рестарт (кэш `catalog_payload`).
- Миграция `ensure_subject_schema()` идемпотентна; существующие аккаунты
  backfill'ятся в `profile_math`. Прямые чтения `users.onboarded/self_level`
  — legacy-зеркало профиля, источник — `user_subjects`.

## 8. Статус профильной математики: что готово, что заблокировано

**Готово**: 20 навыков (№1–№20), 2 раздела, 49 заданий, 20 уроков
(102 EXPLANATION, 87 ACTION, 12 INDEPENDENT_TASK, 9 FOCUS, 11 FEEDBACK),
20 миссий, 2 босса, 8 достижений, daily (6/60 XP), цели g60/g80/g95,
диагностика из 5 заданий, веса/шкала (32 первичных, scale длиной 33),

## 9. Чек-лист: добавить предмет X полностью

1. **Запись предмета** — добавить в `SUBJECTS`: `id (snake_case, напр. basic_math)`,
   `title`, `short`, `status: "empty"`, `forecast: None`. Залить: предмет уже
   выбирается, всё пустое — «готовятся», ничего не сломано.
2. **Шкала прогноза** — `weights` на каждый будущий skill + `total` + `scale`
   длиной `total+1` (монотонная; пропуски шкалы — интерполяцией, как у профиля).
   Без неё предмет останется без прогноза даже с контентом.
3. **Разделы и темы** — `categories[]` ({id, name, short}), `skills[]`
   ({id, name, cat, order, ege}). Проверить: все `cat` существуют, `order`
   без дыр, `id` уникальны глобально (не пересекаются с другими предметами —
   FK не различает предметы, уникальность — договорённость).
4. **Задания** — массив по §3.2. Каждое: атомарный `answer`, `hints[3]` по
   правилам (прогнать `scripts/check_hints.py`, 0 ошибок), `solution` по
   шаблону с дословным `Ответ:`, `valueType` из словаря предмета,
   `type` + `selfCheck` для развёрнутых, `source*/status`, визуал: нет |
   `mathVisual` существующего типа | `visual` с реальным `assetId`.
   Запрещено: выдуманные ответы/рисунки, dictation-хинты, ACTION-ответы прозой.
5. **Ассеты** — файлы в `assets/tasks/…` + записи `visualAssets` +
   `visualAudit: {defaultStatus, taskStatuses[<все id>], references[]}`.
   Правило: `taskStatuses` покрывает **все** задания 1-в-1 (ловит smoke-тест);
   `visual.required` без `assetId` — только если рисунок реально недоступен.
6. **Уроки** — по одному на навык (конвенция): `xp = 60 + 10·steps`, типы шагов
   из §3.3, `INDEPENDENT_TASK.taskId` существует и не blocked.
   Прогнать KaTeX-аудит (`scripts/katex_audit.js`, 0 флагов) + vm-пробу
   (`checkAnswer` принимает все ACTION-ответы, отвергает мусор).
7. **Практика** — `missions[]` (конвенция: миссия на навык, `tasks` — id
   из п. 4), `bosses[]` (`cat` — раздел **этого** предмета, `size/xp/unlockAt`),
   `daily` (`target ≥ 1`, `xp`), `goals[]` (шкала **этого** предмета),
   `diagnosticTasks[]` (существующие, решаемые id; длина = подпись «тест из N»
   в онбординге — сейчас захардкожена «из 5» в `stepDiagnostic`, поправить
   при другой длине).
8. **Установка** — `install_catalog()` (рестарт подхватит), проверить
   `curl /api/bootstrap?subject=X`: `skills/tasks/lessons/missions/diag/goals`
   непусты, `forecast` — конфиг, blocked-id отсутствуют (кроме честно
   заблокированных). Прогнать `node test/smoke.js test/recommender.js
   test/forecast.js` + `EGE_TEST_ADMIN_PASSWORD=… node test/security.js`,
   `node test/admin.js` на живом сервере.
9. **Включение** — `status: "ready"`. Проверить цикл: новый аккаунт →
   выбор X → диагностика → dashboard без заглушек → switch туда-обратно
   (данные обоих предметов целы, `accountId` стабилен) → перезагрузка
   отдаёт текущий предмет.
10. **Админка** — `/api/admin/blocked-tasks` показывает только честные блоки;
    при разделе «Заблокированные» пустом — «задач нет».

## 10. Что прислать для полного запуска базовой математики

Порядок — от блокирующего к тюнингу (п. 1–2 уже можно готовить параллельно):

1. **Структура**: список разделов (напр. «Алгебра», «Геометрия», … — или
   номера 1–21 базы) и тем с номерами (`[{id, name, cat, order, ege}]`).
   `id` — латиницей (`b01_…`), без пересечений с `nXX_*` профиля.
2. **Шкала оценивания базы**: первичные баллы по заданиям → `weights/total`,
   перевод в тестовые (у базы шкала 0–5/зачёт — потому `forecast` отдельный,
   не копия профиля) → `scale`.
3. **Задания** по §3.2 (минимум: миссии и диагностика не соберутся без них).
   Для каждого: условие, ответ (атомарный), 3 хинта, решение, сложность 1–5,
   формат ответа (`valueType`), баллы, источник. Развёрнутые (если есть) —
   только с пометкой самопроверки.
4. **Цели** (`goals:basic_math`, напр. «Зачёт/4/5»), **daily**
   (`target`, `xp`, `title`), **диагностика** (5 id из п. 3).
5. **Уроки** по §3.3 (можно вторым заходом — без них тема считается из
   практики, предмет уже `ready`).
6. **Картинки**: файлы + к каким заданиям; отсутствующие — списком, под них
   `visual.required` без `assetId` (честный блок, не фейк).
7. **Боссы** (по желанию): состав и пороги; миссии соберутся автоматически
   (миссия на навык), достижения общие — присылать не нужно.

Формат передачи — один JSON в структуре `server/catalog.json`
(ключи §2 + полные объекты §3) либо те же таблицы CSV; установка —
`install_catalog()` + проверки из п. 8 чек-листа.
