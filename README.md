# EGE CORE

Рабочий локальный сайт подготовки к ЕГЭ: профильная и базовая математика (ЕГЭ-2027), а также отдельный предмет «Русский язык» с заблокированной темой «Итоговое сочинение».

## Запуск

```bash
python3 server/server.py
```

**Порт 2026** закреплён за этим проектом (символизирует ЕГЭ-2026/2027).

Открой `http://127.0.0.1:2026/`. Каталог и пользовательские данные хранятся в `server/ege.sqlite3`; путь можно изменить через `EGE_DB_PATH`.

`localStorage` используется только для темы интерфейса. Пользовательский прогресс, ответы, ошибки, уроки, XP, streak, статистика и достижения читаются и сохраняются через backend в SQLite.

## Управление процессом

Повторный запуск `python3 server/server.py` безопасен:

- если активен systemd-unit `ege-2026.service`, команда просит systemd выполнить
  `restart` и завершается; новый процесс запускается уже с текущим кодом;
- без systemd используется блокировка и файл `.ege-2026.pid`. Завершается только
  процесс, который ранее записал себя как этот `server.py`; чужой процесс на порту
  не принудительно останавливается.

Для постоянного запуска установи unit из репозитория:

```bash
sudo install -m 0644 deploy/ege-2026.service /etc/systemd/system/ege-2026.service
sudo systemctl daemon-reload
sudo systemctl enable --now ege-2026.service
```

После изменения Python-кода достаточно снова выполнить `python3 server/server.py`
(или `sudo systemctl restart ege-2026.service`). `pkill` для перезапуска не нужен.

## Бэкапы и отказоустойчивость

- **Полные бэкапы** — 2 раза в сутки (04:00 и 16:00 МСК, `EGE_BACKUP_FULL_TIMES`),
  сжатые, в `server/backups/full/`, ротация — последние 14. Страховка: полный
  делается и если с прошлого прошло >12 часов (например, сервер был выключен).
- **Минутные снимки** — каждую минуту (`EGE_BACKUP_INTERVAL_SEC`, по умолчанию
  60), но пишутся только когда БД реально изменилась (сравнение sha256 — в
  простое диск не растёт). Снимаются через онлайн-API SQLite (консистентны под
  нагрузкой), лежат в `server/backups/minutely/`, ротация — последние 180 +
  удаление старше 24 часов.
- **Автовосстановление**: на старте (до миграций) и при каждом коннекте битая
  БД уходит в карантин (`ege.sqlite3.corrupt-<ts>`), на её место встаёт новейший
  проверенный бэкап. Нет здоровых бэкапов — старт с чистой БД: сайт работает.
- **Проверки**: `GET /api/health` (без авторизации) отдаёт `ok`, целостность БД
  и время последних бэкапов. Ручное управление:
  `python3 server/server.py --backup-now | --list-backups | --restore latest|<имя>`.
- Настройки: `EGE_BACKUP_DIR`, `EGE_BACKUP_DISABLE=1` (выключить),
  `EGE_BACKUP_INTERVAL_SEC`, `EGE_BACKUP_FULL_TIMES`.
- SQLite работает в **WAL-режиме** (`synchronous=NORMAL`) — читатели не ждут
  писателя, меньше `database is locked` под параллельными сейвами.

## Защита (DDoS/утечки)

- Общий per-IP лимит API 300 запросов/мин (429 + `Retry-After`), cap 64
  конкурентных запросов (лишние — честный 503), таймаут чтения сокета 30с,
  очередь `request_queue_size=64`.
- Тексты внутренних ошибок (`sqlite3.Error` — схема, пути, блокировки) клиенту
  не отдаются: generic-сообщение + `ref` для поиска в логе.
- Заголовки: `CSP` (без object/frame), `Permissions-Policy`,
  `Cross-Origin-Opener-Policy`, `HSTS` (за HTTPS), баннер версии скрыт.
- Статика не отдаёт БД и служебное: `.sqlite3/-wal/-shm/-journal`, `.bak`,
  `.tmp`, `.log`, каталоги `server/`, `backups/`, `.git`, симлинки; cap 8 МБ.
- Юнит systemd ограничен: `MemoryMax=512M`, `CPUQuota=100%`, `LimitNOFILE=4096`.

## Математические формулы

Во всех полях контента (`text`, `hint`, `solution`, тексты уроков и подсказок)
формулы записываются LaTeX-разметкой: `\\( ... \\)` для формулы внутри строки и
`\\[ ... \\]` для отдельной крупной формулы. Клиент автоматически пропускает эти
фрагменты через единый KaTeX-рендерер. Старые записи с `x²`, `√(...)` и `x^(...)`
поддерживаются для обратной совместимости.

- **Новые номера 2027**: №6 (Случайная величина), №13 (Финансовая математика), №17 (Прикладная оптимизация)
