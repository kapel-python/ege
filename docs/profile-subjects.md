# Где живёт профиль пользователя (предметы без костылей)

## Где живёт профиль пользователя (предметы без костылей)
- `user_subjects(user_id, subject)` — **единственный** источник профиля: `onboarded`, `self_level`, `goal_id`, `state_version`. Любой предмет равноправен; код не сравнивает предмет с «предметом по умолчанию».
- `users.onboarded` — единственная **производная** величина от `user_subjects`: «этот человек реально прошёл онбординг (в любом предмете)». Пересчитывается в одном месте — `refresh_account_onboarded()`, который зовут `patch_settings()` и админский сброс «весь прогресс». Ответ на этот вопрос не зависит от открытого предмета, поэтому новый предмет подхватывается сам.
- `users.self_level` / `users.goal_id` — мёртвое зеркало профиля предмета по умолчанию. Больше не пишется и не читается; миграция `ensure_subject_schema` обнуляет их и пересчитывает `users.onboarded` из `user_subjects` (идемпотентно, один раз на процесс).
- `patch_settings()` — единственное место, применяющее профиль предмета; шкалу целей и самооценку проверяет общий `validate_profile_settings()`, который зовёт и `POST /api/profile/claim`. Заявка о прохождении онбординга самодостаточна: она применяет профиль тем же `patch_settings`, поэтому потерянный ответ не оставляет человека «онбордившимся» локально и «не онбордившимся» в базе.
- Новый предмет = новый `server/subjects/<id>.json` + свой catalog-файл. Ни в `server.py`, ни в `js/` для этого не нужно ни строчки.
