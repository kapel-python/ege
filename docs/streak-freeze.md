# Заморозка и восстановление серии

## Правила показа (сервер = авторитет, клиент — зеркало)
- Серия = дни с учёбой подряд (`streak_activity_dates`: практика, уроки,
  сочинения, ИИ; заход без учёбы не считается).
- Пропуск ровно 1 полного дня (`last == сегодня−2`, серия была ≥ 2) —
  **frozen**: огонёк синий (`.streak-chip--frozen`), показывается прошлое
  значение. Учёба сегодня оттаивает бесплатно → `frozenValue+1`.
- Пропуск 2+ дней — **lost**: показывается 0, прошлое — во `frozenValue`.
- Серия в 1 день не морозится (спасать нечего), новым без активности окно
  не показывается никогда.
- Порог `STREAK_FROZEN_MIN_DAYS = 2` живёт в `server.py` и зеркалится в
  `streakLocalStatus` (`js/app.js`) и `touchStreak` (`js/state.js`) —
  **править тройкой**.

## Мосты (`streak_bridges`) и журнал (`streak_restores`)
- Мост = прощённый пропуск: даёт непрерывность цепочки, но в длину серии
  **не считается** (`display = длина цепочки − мосты в ней`), иначе
  восстановление раздувало бы серию фейковыми днями.
- `kind='auto'` — бесплатная оттайка за учёбу в замороженный день
  (ставит `streak_display_for_write`, лимит не тратит).
- `kind='manual'` — платное восстановление кнопкой; журнал —
  `streak_restores`, месячный ключ — московский `YYYY-MM` дня восстановления.
- **Лимит 3 в месяц на предмет** (`STREAK_RESTORE_MONTHLY_LIMIT`): серия
  живёт в разрезе предмета, общий котёл наказывал бы за второй предмет.
- `streak_restore` идёт в `BEGIN IMMEDIATE` вызывателя: проверка лимита и
  вставка в одной транзакции, гонка двух кликов лимит не пробьёт (перед
  записью журнала — повторная проверка).
- Восстановление прощает **весь** текущий пропуск, ставит
  `user_stats = (frozenValue, вчера)` → статус сразу `active`. Учиться
  сегодня всё равно нужно: иначе завтра снова frozen, послезавтра — lost
  (за новый мост — новое списание).
- После 1 дня учёбы без восстановления серия = 1 и считается ожившей —
  старое значение больше не спасается (только мостами, которых нет).

## Endpoint'ы
- `GET /api/streak?subject=` — авторитетный статус: `streak` (число для
  показа), `status`, `lastActiveDate` (реальная учёба),
  `displayDate` (конец эффективной цепочки — от неё клиент считает показ;
  она же лежит в `user_stats.last_active_date`), `frozenValue`,
  `restoresUsed/Left`, `monthKey`, `canRestore`. Гость — 401.
- `POST /api/streak/restore {subject?}` — те же ворота (бакет, гость 401,
  бан 403, CSRF — общий guard). Ошибки с кодом: `STREAK_ACTIVE`/`STREAK_FROZEN`
  → 409, `RESTORE_LIMIT` → 429, `NOTHING_TO_RESTORE` → 400.

## Клиент (`js/app.js`, стили `css/styles.css`)
- Чип в топбаре и профиле: frozen — синий класс + прошлое число, lost — 0.
  Клик: frozen → окно заморозки, lost с прошлым ≥ 2 → окно восстановления
  с лимитами, иначе — старая подсказка `openHelp('streak')`.
- Окна — та же `.dlg`-система (`openInfoDialog` + кастомный `.dlg` с
  лимитами для восстановления, своих стилей нет). У заморозки кнопок
  действий нет (только «Понятно»): вернуть серию можно лишь учёбой.
  Кнопка «Восстановить» — `disabled` (серая) при исчерпанном лимите.
- Автопоказ: один раз за загрузку страницы, через 2 с после входа, только
  внутри SPA (`index.html` — статичные страницы этот код не исполняют),
  только onboarded + доступный предмет, не поверх других окон/онбординга/
  пикера/блокировки. После восстановления — `displayDate` в стейт, иначе
  показ тут же вернулся бы к 0 до перезагрузки.
- `touchStreak` продолжает замороженную серию сразу верным числом
  (иначе счётчик и таймлайн мигали бы единицей до перезагрузки).

## Сбросы и тесты
- Админ-сброс «streak» и «весь прогресс» чистят `streak_bridges` +
  `streak_restores`, иначе серия воскресала бы из мостов при первой записи.
  `DELETE /api/state` — каскадом через `ON DELETE CASCADE`.
- Тесты (из корня): `python3 test/streak-freeze.py` (ядро, офлайн),
  `node test/streak-freeze-ui.js` (зеркало клиента + врезка),
  `python3 test/streak-freeze-http.py` (HTTP на temp-БД).
